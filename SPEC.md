# Техническая спецификация pi-strata

## 1. Назначение и границы

pi-strata — расширение Pi Coding Agent для послойной компактизации контекста. Оно сохраняет исследование, план и технические отчёты, а эфемерные логи удаляет на границах фаз или суммаризует при обычной компактизации.

Детерминированный префикс предназначен для переиспользования KV-кэша локальными LLM (llama.cpp, Ollama и совместимыми серверами). Фактическое попадание в кэш зависит от провайдера. Оценка токенов, задержка и поля usage не считаются самостоятельным доказательством cache hit; используются только явно сообщённые провайдером метрики.

Состояние слоёв хранится в разговоре. Файлы `<session>.pi_strata/tmp/` содержат только восстановимые сырые снапшоты и не являются источником состояния плана.

## 2. Модель контекста

```text
[Layer 0] системный промпт + статичные инструкции pi-strata
  [RESEARCH] исследование текущей задачи
    [PLAN] базовый план
      [MILESTONE-N] дайджесты архивированных отчётов
        [STEP-ID] отчёты завершённых шагов
          [PLAN-DELTA] полный новый эффективный план
            [current] текущая работа и вывод инструментов
```

Каноническая summary начинается с `## PI-STRATA CONTEXT (v1)`. Блоки выводятся строго в порядке **RESEARCH → PLAN → MILESTONE → STEP → PLAN-DELTA**, нормализуются и соединяются через `\n\n`. Повторная сборка уже канонических слоёв не меняет их байты. Динамический LLM-хвост всегда находится после них.

Маркер блока:

```text
/*STRATA::<KEY>::v1*/
тело
/*STRATA::END::<KEY>::v1*/
```

Поддерживаются `RESEARCH`, `PLAN`, `PLAN-DELTA`, `MILESTONE-N` и `STEP-ID`. Незакрытые и пустые блоки игнорируются. Последний применимый блок того же ключа заменяет предыдущий.

Новым маркерам доверяют только в тексте ассистента и в каноническом префиксе предыдущей strata-summary. Маркеры в user/tool-сообщениях не изменяют слои. Маркеры в неканоническом LLM-хвосте также не входят в доверенный префикс.

## 3. План и завершение шагов

Новый пункт плана записывается со стабильным уникальным ID:

```text
- [id:S1] Изменить src/example.ts, запустить npm test и записать результат
```

ID соответствует `[A-Za-z0-9][A-Za-z0-9_-]*`. Действие пункта должно быть самодостаточным: файлы/модули, конкретная работа, команды проверки и ожидаемый результат.

Отчёт использует тот же ID: `STEP-S1`. Он содержит выполненную работу, изменённые файлы, результаты проверок, решения, риски и путь к сырому снапшоту. Прогресс вычисляется из STEP и `Completed-Steps` в MILESTONE, а не из чекбоксов.

Старые числовые `STEP-N` и планы без явных ID остаются читаемыми. Их ID выводится из позиции пункта. Инструмент принимает как строковый ID, так и legacy numeric position; число должно быть целым и не меньше 1.

`PLAN-DELTA` содержит **полный новый эффективный план**, а не список изменений. Базовый PLAN остаётся неизменным. Завершённые пункты нельзя удалять или менять их ID/текст; новые работы получают свежие ID. Дубликаты ID и STEP без соответствующего пункта отклоняются. Шаги выполняются в порядке эффективного плана.

Новый RESEARCH начинает новый цикл: очищает PLAN, PLAN-DELTA, STEP и MILESTONE. До принятия `advance` требуется новый базовый PLAN; старый план не наследуется.

## 4. Пайплайн и фазовая компактизация

1. В strict-режиме пайплайн применяется к каждой задаче реализации. В light-режиме вопросы и небольшие задачи выполняются обычно, а пайплайн начинается только для существенной работы.
2. Модель записывает RESEARCH и PLAN, затем вызывает `strata(action="advance")`.
3. После выполнения пункта модель записывает STEP-ID и вызывает `strata(action="advance", step="ID")`.
4. После принятия advance расширение добавляет custom entry `strata-phase-boundary`. Этот sentinel сохраняется в дереве сессии, но не проецируется в LLM-контекст.
5. На `agent_settled` запрашивается компактизация. В plan/step-режиме `firstKeptEntryId` указывает на sentinel, поэтому после компактизации остаётся каноническая strata-summary без сырых логов и без LLM-хвоста pi.
6. При успешной step-компактизации сырой discarded + retained контекст сохраняется в `tmp/step_ID_raw.md`. Создание sentinel само по себе не создаёт summary или снапшот.

Публичный API pi перед `session_before_compact` выполняет model/auth preflight и подготовку компактизации. Он может отказать в компактизации малой сессии до вызова расширения. Поэтому pi-strata не объявляет forced compaction гарантированной: ошибка переводит advance в явный **deferred/degraded mode**, pending очищается, пайплайн продолжается с полной фазой в контексте, а следующий advance повторяет попытку. Для гарантированной принудительной компактизации малой сессии требуется отдельная поддержка upstream API.

## 5. Обычная компактизация strata-сессии

Автоматическая overflow-компактизация и `/strata compact` вне pending-фазы используют plain-режим:

1. канонические слои извлекаются из доверенных источников;
2. `firstKeptEntryId` pi не меняется, обычный retained tail сохраняется;
3. STRATA-блоки структурно удаляются из assistant-сообщений, переданных стандартному суммаризатору pi;
4. предыдущий LLM-хвост отделяется от канонического префикса и участвует в обычном merge;
5. summary эфемерной работы добавляется после слоёв.

Если LLM недоступна или суммаризация завершилась ошибкой, добавляется `PI-STRATA RAW CHECKPOINT`: не более последних 12 000 символов очищенного discarded-контекста. Это ограниченный fallback вместо потери незавершённой работы. Abort не маскируется и отменяет операцию.

Если несколько расширений обрабатывают `session_before_compact`, побеждает результат последнего обработчика. pi-strata помечает свой результат через `details.strata` и предупреждает, если сохранённая summary была заменена.

## 6. Бюджет постоянных слоёв и MILESTONE

`layerTokenBudget` по умолчанию равен 16384 оценочным токенам. Оценка всей канонической summary — `ceil(characters / 4)`, а не tokenizer провайдера. Значение `0` отключает ротацию.

При превышении бюджета и наличии STEP-отчётов:

1. полные слои до ротации сохраняются в `tmp/epoch_N_layers.md`;
2. milestone-суммаризатор получает все слои, включая отчёты, и создаёт долговременный дайджест;
3. добавляется MILESTONE-N с полным списком `Completed-Steps`;
4. только после успешной суммаризации индивидуальные STEP-отчёты удаляются из активных слоёв.

При ошибке milestone-суммаризации отчёты сохраняются полностью. Архивированные ID продолжают участвовать в прогрессе, разблокировке следующих шагов и проверке неизменности завершённых пунктов.

## 7. Режимы, автопродолжение и UI

Режим является сессионным состоянием и по умолчанию выключен. Новая, возобновлённая и перезагруженная сессия начинается с off; исторические `piStrata.enabled` и `PI_STRATA_ENABLED` игнорируются.

- `/strata-on [strict|light]` включает режим.
- `/strata-off` выключает режим, очищает pending и отправляет отзыв standing instructions. Далее используется обычная компактизация pi, а `advance` отклоняется.
- `/strata pause` приостанавливает только автопродолжение.
- `/strata resume` возобновляет его и в простое ставит следующий пункт в очередь.
- `/strata` показывает статус; `/strata compact` запрашивает ручную компактизацию; `/strata reset` после подтверждения удаляет сырые снапшоты.

При включении в непустой сессии инструкции сначала отправляются custom message в конец контекста, чтобы не менять системный префикс. После следующей компактизации они переносятся в системный промпт. В пустой сессии системный промпт обновляется сразу.

После завершения или deferred-ошибки advance `autoContinue` ставит следующий незавершённый пункт в очередь, если режим не поставлен на паузу.

TUI показывает либо прогресс эффективного плана, либо strict/light/off/paused. Маркеры скрываются только при отображении. Статус содержит оценку размера слоёв, бюджет, epoch, счётчики успешных/deferred-компактизаций и последние provider-reported `cacheRead/input`.

## 8. Конфигурация

Приоритет каждого поля: environment → project settings → global settings → default. Невалидное значение игнорируется, после чего применяется следующий источник.

| Environment | `piStrata` в settings.json | Default |
| --- | --- | --- |
| `PI_STRATA_AUTO_CONTINUE` | `autoContinue` | `true` |
| `PI_STRATA_HIDE_ANCHORS` | `hideAnchors` | `true` |
| `PI_STRATA_LAYER_TOKEN_BUDGET` | `layerTokenBudget` | `16384` |

Boolean env принимает без учёта регистра `1/true/on` и `0/false/off`. Бюджет должен быть неотрицательным целым. Файлы: `~/.pi/agent/settings.json` и `<project>/.pi/settings.json`.

## 9. Проверка

```bash
npm test
npm run typecheck
npm run test:local
```

Offline self-test покрывает протокол, команды, fallback, rollover и реальные публичные `buildContextEntries`/`buildSessionContext` pi для sentinel. `test:local` требует `PI_STRATA_TEST_URL` и `PI_STRATA_TEST_MODEL`; `PI_STRATA_TEST_API_KEY` необязателен. Без endpoint проверка завершается со `SKIP`. Cache read сообщается только при явной положительной cached-token метрике провайдера.
