# pi-episteme

**Продвинутая компактизация контекста** для
[pi-coding-agent](https://github.com/badlogic/pi-mono) с локальными LLM.

Пайплайн «исследование → план → шаги», который сохраняет долговременное
состояние задачи и удаляет эфемерные логи на границах фаз. План выполняет сам
агент сессии — никаких прогонов субагентов. Детерминированный префикс
рассчитан на переиспользование KV-кэша локальными серверами вроде llama.cpp и
Ollama. Фактическое кэширование зависит от провайдера: pi-episteme не считает
задержку или оценку токенов доказательством попадания в кэш.

Спецификация: [`SPEC.md`](./SPEC.md). English README:
[`README.md`](./README.md).

## Модель контекста

Модель записывает долговременные блоки между точными маркерами `EPISTEME`.
Расширение извлекает их и детерминированно собирает summary; состояние слоёв
находится в разговоре, а не в файлах слоёв.

```text
[Layer 0] системный промпт + статичные инструкции pi-episteme
  [RESEARCH] исследование текущей задачи
    [PLAN] базовый план со стабильными ID пунктов
      [MILESTONE-N] необязательные дайджесты архивированных отчётов
        [STEP-ID] отчёты о завершённых шагах
          [PLAN-DELTA] необязательная полная замена эффективного плана
            [текущее] эфемерная работа и вывод инструментов
```

Канонический порядок summary: **RESEARCH → PLAN → MILESTONE → STEP →
PLAN-DELTA**, независимо от порядка обнаружения блоков. Блоки разделяются ровно
одной пустой строкой. Действует последний применимый блок; незакрытые и пустые
блоки игнорируются.

Каждый пункт плана имеет стабильный уникальный ID:

```text
- [id:S1] Изменить src/example.ts, запустить npm test и записать ожидаемый результат
```

PLAN и PLAN-DELTA — **плоские списки**: один пункт на строку, маркер `-` в
нулевой колонке. Вложенные подпункты, строки прозы и строки внутри code fence
пунктами не считаются: каждый отслеживаемый пункт обязан получить STEP-отчёт,
поэтому вложенный план породил бы пункты, которые никогда нечем закрыть.
Подробности пишите в тексте пункта или в RESEARCH; неотмеченная строка с
отступом читается как продолжение предыдущего пункта.

Его отчёт — `STEP-S1` между `/*EPISTEME::STEP-S1::v1*/` и
`/*EPISTEME::END::STEP-S1::v1*/`. Старые сессии с числовыми отчётами `STEP-N`
остаются читаемыми, а инструмент по-прежнему принимает числовую позицию шага.
В новых планах следует использовать явные ID.

Прогресс определяется отчётами STEP и записями `Completed-Steps` в MILESTONE,
**а не чекбоксами плана**. Не нужно перевыпускать PLAN для отметок. Для
изменения работы выдаётся PLAN-DELTA с **полным новым эффективным планом**:
ID и текст действий завершённых пунктов сохраняются, новая работа получает
новые ID. PLAN-DELTA канонически располагается после отчётов; базовый PLAN не
переписывается.

Новый **RESEARCH начинает новый цикл задачи**. Он очищает прежние PLAN,
PLAN-DELTA, отчёты STEP и MILESTONE. Старый план не наследуется: до принятия
`advance` требуется новый базовый PLAN.

## Пайплайн и компактизация

1. Episteme — состояние сессии, по умолчанию **выключено**. `/episteme-on`
   включает его для сессии: агент сессии работает один — сам пишет
   RESEARCH/PLAN, реализует пункты по порядку, закрывает каждый
   STEP-ID-отчётом и `advance`; вопросы и мелкие задачи остаются без
   маркеров. `/episteme-off` выключает режим снова.
2. В существующем разговоре постоянные инструкции сначала добавляются
   сообщением, чтобы не менять кэшированный системный префикс; после следующей
   компактизации они переезжают в системный промпт. В пустой сессии они сразу
   добавляются в системный промпт.
3. Модель пишет RESEARCH и новый базовый PLAN, затем вызывает
   `episteme(action="advance")`. Пункты выполняются по порядку. После каждого
   пишется STEP-ID отчёт и вызывается
   `episteme(action="advance", step="S1")`.
4. Advance создаёт sentinel границы фазы, который не попадает в контекст, и
   запрашивает компактизацию в конце хода. Если компактизация действительно
   выполняется, режим plan/step обрезает историю по sentinel и оставляет только
   детерминированное episteme-summary — без LLM-хвоста pi. При успешной фазе шага
   сырой контекст также сохраняется в
   `<сессия>.pi_episteme/tmp/step_S1_raw.md`; этот путь нужно указать в отчёте.
   Само создание sentinel не создаёт ни summary, ни снапшот.
5. Остальные компактизации включённой сессии (переполнение или
   `/episteme compact`) работают в plain-режиме. Они сохраняют обычный retained
   tail pi, удаляют слои episteme из входа plain-суммаризатора и добавляют его
   summary эфемерной работы после канонических слоёв. Новым маркерам доверяют
   только в тексте ассистента и предыдущем каноническом episteme-summary, но не
   в тексте пользователя или инструментов. При сбое plain LLM-суммаризации
   добавляется ограниченный raw checkpoint — последние 12 000 символов
   очищенного отбрасываемого контекста; отмена операции по-прежнему
   пробрасывается. Блок слоя, чей текст дословно остался в сохраняемом хвосте,
   не дублируется в summary (список таких блоков — `dedupedWithTail` в
   деталях компактизации); ничего не теряется — на следующей компактизации
   копия из хвоста снова складывается в канонические слои. Отменённая
   компактизация сохраняет phase-границу: фаза повторяется на следующем
   advance, а не исчезает молча.
6. Если pi отклоняет advance-компактизацию малой сессии/ручную компактизацию
   или ей мешает auth preflight, UI и статус явно показывают
   **deferred/degraded compaction**. Пайплайн продолжается с полной фазой в
   контексте, а следующий advance повторяет попытку. Для действительно
   принудительной компактизации малой сессии нужна поддержка API upstream pi;
   pi-episteme не гарантирует выполнение каждого запроса компактизации.

`/episteme-off` выключает пайплайн для сессии, отменяет ожидающий phase-запрос и
ставит в очередь уведомление, отзывающее постоянные инструкции. В выключенном
состоянии работает обычная компактизация pi, `advance` отклоняется, а `status`
доступен. Возобновлённые сессии тоже начинаются выключенными; при обнаружении
слоёв выводится подсказка.

## Бюджет слоёв и ротация через MILESTONE### Ротация через MILESTONE

`layerTokenBudget` по умолчанию равен **16384 оценочным токенам**: оценка всего
канонического summary слоёв — `ceil(число символов / 4)`. Значение `0`
отключает ротацию. Это локальная оценка, а не число токенов провайдера.

При превышении бюджета и наличии STEP-отчётов pi-episteme:

1. сохраняет полные слои до ротации в `tmp/epoch_N_layers.md`;
2. запрашивает у milestone-суммаризатора долговременный дайджест — он
   намеренно получает **все слои**, включая отчёты;
3. после успешной суммаризации добавляет MILESTONE-N с сохранённым списком ID
   `Completed-Steps` и очищает отдельные отчёты.

Если milestone-суммаризация не удалась, полные отчёты остаются в слоях;
прогресс не выбрасывается. Это отличается от plain-суммаризации, из входа
которой слои исключаются.

## Автопродолжение и UI

`autoContinue` включено по умолчанию. После обработки advance, включая явно
обозначенное degraded-продолжение, в очередь ставится следующий незавершённый
пункт. Собственный порог pi проверяется между ходами — сразу после добавления
результата tool-вызова, до завершения рана, — поэтому пороговая или
overflow-компактизация может закрыть фазу первой; тогда продолжение не теряется
вместе с потреблённым запросом фазы, а остаётся «долгом» и ставится в очередь на
ближайшем `agent_settled`. `/episteme pause` останавливает только
автопродолжение, но не выполнение или компактизацию; `/episteme resume` включает
его снова и в простое ставит следующий пункт в очередь.

TUI показывает прогресс плана либо состояние on/off/paused, когда плана ещё
нет. Якоря
маркеров по умолчанию скрыты только на экране: в сессии и контексте модели они
сохраняются. `/episteme reset` удаляет сырые снапшоты. Каталоги снапшотов
удалённых сессий очищаются при старте сессии.

`/episteme` и `episteme(action="status")` показывают размер слоёв, epoch, счётчики
компактизаций и последние usage-поля ассистента как `cacheRead/input`. Токены
слоёв — локальная оценка, а cache/input — значения, сообщённые провайдером;
ни то ни другое не доказывает попадание в KV-кэш.

## Установка

```bash
# из git (зафиксированный ref):
pi install git:github.com/maxsintsov1996-netizen/pi-episteme@v0.3.0
# или из локального каталога:
pi install /path/to/pi-episteme
```

> npm: `pi install npm:pi-episteme` заработает после публикации v0.3.0 в
> реестре. На момент написания пакета в реестре не было (`npm view pi-episteme`
> отвечает 404), поэтому документированный путь — git или локальный каталог.

Требуется Node.js **22.19.0 или новее**. TypeScript загружается средой pi;
сборка не нужна.

Peer-зависимости пакета: `@earendil-works/pi-ai`,
`@earendil-works/pi-coding-agent` и `@earendil-works/pi-tui` (все `>=0.85.0` —
линейка, на которой расширение разрабатывается и тестируется) и `typebox`
(`>=1.0.0`). Dev-зависимости: `@types/node` и `typescript`. Необязательный локальный
smoke-скрипт использует встроенные в Node API `fetch`, `URL` и `performance`
и не добавляет runtime-зависимостей.

## Команды и инструмент

- `episteme(action="advance")` — принять новый базовый PLAN или полный
  PLAN-DELTA и запросить phase-компактизацию.
- `episteme(action="advance", step="S1")` — принять отчёт по стабильному ID.
  Числовой `step`, например `step=1`, поддерживается как старая позиция в
  плане; это должен быть целый номер не меньше 1. Строковые ID соответствуют
  `[A-Za-z0-9][A-Za-z0-9_-]*`.
- `episteme(action="status")` — показать состояние и оценки usage/статуса.
- `/episteme` — статус; `/episteme compact` — запросить ручную компактизацию;
  `/episteme reset` —
  после подтверждения удалить сырые снапшоты этой сессии. Неизвестная
  подкоманда сообщит об этом, а не молча покажет статус.
- `/episteme pause` и `/episteme resume` — приостановить/возобновить
  автопродолжение.
- `/episteme-on` — включить режим для этой сессии.
- `/episteme-off` — выключить режим и отозвать постоянные инструкции.

## Конфигурация

Приоритет каждого поля: **окружение > настройки проекта > глобальные настройки
> значение по умолчанию**. Невалидное значение пропускается, и проверяется
следующий источник. Файлы: `~/.pi/agent/settings.json` и
`<проект>/.pi/settings.json`, секция `piEpisteme`.

| Окружение | settings.json | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `PI_EPISTEME_AUTO_CONTINUE` | `piEpisteme.autoContinue` | `true` | Ставить следующий незавершённый пункт в очередь после advance |
| `PI_EPISTEME_HIDE_ANCHORS` | `piEpisteme.hideAnchors` | `true` | Скрывать якоря маркеров только в TUI |
| `PI_EPISTEME_LAYER_TOKEN_BUDGET` | `piEpisteme.layerTokenBudget` | `16384` | Оценочный бюджет слоёв; `0` отключает MILESTONE-ротацию (только safe integer) |

Булевы переменные окружения разбираются строго, без учёта регистра и с обрезкой
пробелов: истина — `1`, `true`, `on`; ложь — `0`, `false`, `off`. Остальные
значения невалидны и игнорируются. Бюджет в окружении должен быть
неотрицательным десятичным целым, а в JSON — неотрицательным целым числом.
Старые `PI_EPISTEME_ENABLED` и `piEpisteme.enabled` не включают сессию.

Пример:

```json
{
  "piEpisteme": {
    "autoContinue": false,
    "hideAnchors": true,
    "layerTokenBudget": 16384
  }
}
```

## Структура и проверка

```text
index.ts        — события сессии, команды, инструмент, виджеты
prompts.ts      — все тексты для модели (layer-0 протокол)
compaction.ts   — компактизация plan/step/plain, MILESTONE, raw fallback
episteme.ts     — маркеры, планы со стабильными ID, извлечение, канонические summary
config.ts       — разрешение окружения/настроек и значения по умолчанию
check.cjs       — офлайн self-test
local-check.cjs — необязательная smoke-проверка OpenAI-совместимого endpoint
```

```bash
npm test
npm run typecheck
npm run test:local
```

`test:local` запускается только по явному запросу и завершается со `SKIP`, если
не заданы обе переменные `PI_EPISTEME_TEST_URL` и `PI_EPISTEME_TEST_MODEL`.
`PI_EPISTEME_TEST_API_KEY` необязателен. Скрипт отправляет два запроса со
стабильным префиксом и дописанным эфемерным хвостом, затем выводит доступные
usage/timings. Cache read засчитывается **только при явно возвращённой
провайдером положительной метрике cached tokens**; иначе переиспользование кэша
считается непроверенным.
